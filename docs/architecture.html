สถาปัตยกรรม

โค้ดแบ่งเป็นโมดูลเล็ก ๆ มีหน้าที่เดียวต่อไฟล์ — Node.js จัดคิว, libvips (C++) ทำงานหนัก, logger จดทุกอย่าง

โมดูล

ไฟล์หน้าที่
src/cli.jsentry — แยก args (commander); ถ้าไม่ส่ง args เข้า interactive prompts
src/run.jsorchestrator — scan → sharp.concurrency() → worker pool → progress → summary → logger.flush()
src/scanner.jsเดินโฟลเดอร์ กรองนามสกุลรูป 13 ชนิด, exclude output dir + _logs + hidden
src/converter.jspipeline ต่อรูป — metadata → rotate(EXIF) → keepIccProfile → resize(inside, withoutEnlargement) → jpeg(q, progressive) → toFile(.part) → rename
src/pool.jsworker pool ขนาดคงที่ (ไม่ใช้ worker_threads — libvips มีเธรด C++ ของตัวเอง)
src/logger.jsdual-format logger — รวมบรรทัดในหน่วยความจำ, flush ครั้งเดียวตอนจบ
src/interactive.jsprompts — ลากวาง path ได้, ตัด quote อัตโนมัติ, ตรวจโฟลเดอร์จริง
scripts/make-samples (รูปทดสอบ), benchmark (วัด concurrency), gen-chart (กราฟ SVG), test-run (e2e)

การไหลของงาน

1

Scan

รวมไฟล์รูป (recursive ตาม option) เรียงชื่อ — log เทียบข้ามรันได้

2

Plan concurrency

workers = จำนวนคอร์, pin sharp.concurrency(1) เมื่อ workers > 1 (หลักฐานใน RESEARCH)

3

Pool

N runner หยิบไฟล์ต่อเมื่อว่าง — disk I/O กับ CPU ซ้อนกันเต็มเวลา

4

Per-file pipeline

ไฟล์ตาย = error รายไฟล์ (failOn:none + try/catch) · เขียน .part แล้ว rename (atomic)

5

Progress + collect

progress bar ต่อเสร็จ; เก็บมิติ/ไบต์/ms ต่อรูปเพื่อสรุป

6

Summary + flush

console summary, top-5, เขียน .log + .jsonl + summary.json + latest.*

การตัดสินใจเด่น

คำถามคำตอบ
ทำไมไม่ใช้ worker_threadsงานฝั่ง JS ต่อรูปเบามาก คอขวดคือ decode/encode ใน C++ — libvips ขนานเองอยู่แล้ว (หลักฐาน: RESEARCH)
ทำไม logger ไม่ append ทันทีเขียน log 4,904 ครั้ง = I/O overhead ฟรี ๆ — flush ครั้งเดียวต่อรันเร็วกว่ามาก (แลก: รันที่ถูก kill ไม่มี log แต่รูปยังครบ)
ทำไม output เป็นโฟลเดอร์ข้างเคียงตัด bug คลาสสิก "สแกนเจอผลลัพธ์ตัวเอง" ตั้งแต่ต้น
ทำไมคง ICC แต่ตัด EXIFสีถูกต้องข้ามอุปกรณ์ + ตัดข้อมูลส่วนบุคคล (GPS/รุ่นกล้อง) เป็น default ที่ปลอดภัย

Exit codes

รหัสความหมาย
0สำเร็จ (หรือ skipped ทั้งหมด)
1ระบบล้มก่อนเริ่ม (พาธผิด, config ผิด)
2จบแต่มีบางไฟล์ error (ค้น file_error ใน log)
