v1.0.3 — 1 ตุลาคม 2026 bugfix

แก้ไข (Fixed)

  • โหมด interactive (resize.bat) เด้ง Error: Path not found เมื่อกด Enter ผ่าน default ของ Output folder — default (<input>/<size> เช่น Photos\3800) ยังไม่มีอยู่จริงจนกว่าเครื่องมือจะสร้างเอง แต่โค้ดตรวจ existence ด้วย (มีตั้งแต่ v1.0.0) — ตอนนี้ตรวจเฉพาะ input; output สร้างให้อัตโนมัติ
  • Ctrl+C ระหว่างคำถาม → จบอย่างสวยงาม ("Cancelled.") แทน TypeError
  • เพิ่ม e2e test จำลอง flow interactive (inject prompt) ครอบเคสนี้ถาวร

v1.0.2 — 1 ตุลาคม 2026 performance

เคาะ default ใหม่เพื่อความเร็วสูงสุด (Changed)

  • JPEG baseline เป็น default (แทน progressive) — encode เร็วขึ้น ~33% ไฟล์ใหญ่ขึ้นเพียง ~3%; ต้องการ progressive ใช้ --progressive
  • kernel cubic เป็น default (แทน lanczos3) — เร็วขึ้น ~10%; ต้องการความคมสูงสุดใช้ --kernel lanczos3
  • output เริ่มต้นอยู่ในโฟลเดอร์ต้นฉบับ ชื่อตามขนาด: <input>/<max-size> เช่น Photos\3800 — scanner ตัดโฟลเดอร์นี้ออกเสมอ + e2e test ยืนยันว่ารันซ้ำไม่เกิด nesting; เปลี่ยนได้ด้วย -o
  • ผลรวม: ~330 MP/s (+25% จาก v1.0.1, +78% สะสมจาก v1.0.0) — โฟลเดอร์ 4,904 รูป 25 GB ≈ 3.5 นาที
  • การตัดสินใจทั้งหมดอ้างข้อมูลจากการแยก profile รายขั้นของ pipeline (ดู RESEARCH หัวข้อ 7)

v1.0.1 — 1 ตุลาคม 2026 performance

แก้คอขวดที่ซ่อนอยู่ (Performance)

  • ตัวการจริงคือ libuv threadpool ของ Node ที่ default มีแค่ 4 เธรด — sharp รัน pipeline บน pool นี้ จึงมีงานพร้อมกันจริงแค่ 4 เสมอ (CPU วิ่ง ~53%)
  • ตั้ง UV_THREADPOOL_SIZE = จำนวนคอร์อัตโนมัติผ่าน src/entry.mjs และ launchers
  • ผลจริงบน i9-9900K: 185 → 262 MP/s (+42%), CPU 53% → 94% (ชุด 240 รูป: 21.5s → 14.8s)
  • ปิด vips operation cache — งานผ่านครั้งเดียวไม่ได้ประโยชน์จาก cache
  • เพิ่ม --skip-smaller — ข้ามรูปที่เล็กกว่า limit อยู่แล้วโดยไม่แปลง (ชุดรูปผสมเร็วขึ้นมาก)
  • วิเคราะห์ฉบับเต็ม 3 ก้าว (พบความผิดปกติ → ทดสอบยืนยัน → benchmark ทางการ) ใน RESEARCH

v1.0.0 — 1 ตุลาคม 2026 release

เพิ่มใหม่ (Added)

  • CLI ย่อรูปทั้งโฟลเดอร์เป็น JPG: กำหนดความยาวด้านสูงสุดได้ (default 3800px), คุณภาพ JPEG, recursive, resume-safe
  • แปลงข้ามฟอร์แมต: jpg / jpeg / jfif / png / webp / tiff / gif / svg / avif / heic / heif → .jpg
  • Auto-rotate ตาม EXIF orientation + คง ICC colour profile (ตัด EXIF/GPS ตาม default, เปิด --keep-metadata เพื่อเก็บ)
  • ระบบ log ครบต่อรัน: .log (คนอ่าน) + .jsonl (เครื่องอ่าน) + summary.json + latest.*
  • โหมดใช้งาน: interactive (ดับเบิลคลิก resize.bat / npm start), CLI เต็มรูปแบบ, --dry-run
  • Concurrency อัตโนมัติ: workers = จำนวนคอร์ + sharp.concurrency(1) — พิสูจน์ด้วย benchmark (ดู RESEARCH)
  • Atomic write (.part → rename): ขัดจังหวะกลางทางได้ ไม่มีไฟล์ครึ่งกลาง
  • Flags: --mozjpeg, --overwrite, --quiet, --log-level, --log-dir, --sharp-concurrency
  • เอกสารครบ md + HTML: README, USAGE, RESEARCH (กราฟจากข้อมูลจริง), LOGGING, ARCHITECTURE, CHANGELOG
  • GitHub Pages: หน้าดาวน์โหลดดึง release ล่าสุดจาก GitHub API อัตโนมัติ
  • Release assets: แพ็กเกจพกพา Windows x64 (Node runtime + node_modules ในตัว) + ซอร์สโค้ด zip + SHA256SUMS

ประสิทธิภาพ (i9-9900K, ภาพ 14.2 MP → 3800px, q82)

  • v1.0.0: ~185 MP/s (CPU 53%) — แก้ต่อที่ v1.0.1 เหลือ 262 MP/s (CPU 94%); เร่งจากเธรดเดียว 5.1 เท่า
  • ขนาดรวมลดลง 78% (233 MB → 51 MB) ในชุดทดสอบ 48 รูป
