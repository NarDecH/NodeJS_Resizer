# คู่มือการใช้งาน (USAGE)

เวอร์ชัน HTML ที่อ่านง่าย: [usage.html](https://nardech.github.io/NodeJS_Resizer/usage.html)

## 3 วิธีเริ่มใช้งาน

### 1) ดาวน์โหลดโปรแกรมสำเร็จรูป — ง่ายสุด (Windows)

1. เข้า [หน้าดาวน์โหลด](https://nardech.github.io/NodeJS_Resizer/) แล้วกดโหลดไฟล์ `…win-x64-portable.zip`
2. คลิกขวา → **Extract All** (แตก zip)
3. ดับเบิลคลิก **`resize.bat`**
4. ลากโฟลเดอร์รูปใส่หน้าต่างโปรแกรม → กด Enter → รอจบ

ในแพ็กเกจนี้มี Node.js runtime และไลบรารีครบ ไม่ต้องติดตั้งอะไรเพิ่ม ใช้จาก USB ก็ได้

### 2) ผ่าน Node.js/npm

```bash
git clone https://github.com/NarDecH/NodeJS_Resizer.git
cd NodeJS_Resizer
npm install
npm start            # เข้าโหมดถาม-ตอบ เหมือนดับเบิลคลิก resize.bat
```

### 3) สั่งงานเต็มรูปแบบ (สคริปต์/งานอัตโนมัติ)

```bash
node src/cli.js -i "D:\Photos" -o "D:\Photos-resized" -s 3800 -q 82
```

## ตัวอย่างการสั่งงานที่ใช้บ่อย

```bash
# ทั้งโฟลเดอร์ ยาวสุด 3800px (ค่าเริ่มต้น) โยนผลลัพธ์ไปโฟลเดอร์ข้าง ๆ
node src/cli.js -i "D:\Photos"

# คุณภาพสูงขึ้น + ไฟล์เล็กลงแบบ mozjpeg (ช้าลง 2-3 เท่า)
node src/cli.js -i "D:\Photos" -q 92 --mozjpeg

# จำกัดขนาด 1920px สำหรับเว็บ, เฉพาะไฟล์ในโฟลเดอร์เดียว ไม่ลงโฟลเดอร์ย่อย
node src/cli.js -i "D:\Gallery" -s 1920 --no-recursive

# ทดลองดูก่อนว่าจะเกิดอะไรขึ้น โดยไม่เขียนไฟล์
node src/cli.js -i "D:\Photos" --dry-run

# รันต่อจากที่เดิมค้าง (ข้ามไฟล์ที่ทำเสร็จแล้วโดยอัตโนมัติ)
node src/cli.js -i "D:\Photos"           # รันซ้ำได้เรื่อย ๆ ปลอดภัย

# เก็บ EXIF/GPS ไว้ด้วย (เช่น งานถ่ายภาพที่ต้องการข้อมูลกล้อง)
node src/cli.js -i "D:\Wedding" --keep-metadata

# บังคับทำใหม่ทุกไฟล์ ทั้งที่เคยทำแล้ว
node src/cli.js -i "D:\Photos" --overwrite
```

## ตารางตัวเลือกทั้งหมด

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `-i, --input <dir>` | ถามตอนรัน | โฟลเดอร์ต้นทาง (หรือพาธไฟล์เดียว) — ลากวางใส่หน้าต่างได้เลย |
| `-o, --output <dir>` | `<input>-resized` | โฟลเดอร์ปลายทาง; เก็บโครงสร้างโฟลเดอร์ย่อยเดิม |
| `-s, --max-size <px>` | `3800` | ขนาดด้านที่ยาวที่สุดที่อนุญาต (16–30000) |
| `-q, --quality <n>` | `82` | คุณภาพ JPEG 1–100 |
| `-w, --workers <n>` | `auto` | จำนวนรูปที่ประมวลผลพร้อมกัน (`auto` = จำนวนคอร์ CPU) |
| `--no-recursive` | (recursive อยู่) | ไม่ลงไปในโฟลเดอร์ย่อย |
| `--overwrite` | ปิด | แปลงซ้ำทุกไฟล์ (default = ข้ามไฟล์ที่มีผลลัพธ์แล้ว เพื่อ resume) |
| `--keep-metadata` | ปิด | เก็บ EXIF/GPS (default ตัดทิ้ง แต่คง ICC colour profile ไว้เสมอ) |
| `--mozjpeg` | ปิด | ใช้ mozjpeg — เล็กลง ~30% แต่ช้าลง 2–3 เท่า |
| `--dry-run` | ปิด | วางแผน/สร้าง log อย่างเดียว ไม่เขียนรูป |
| `--log-level <lvl>` | `info` | `debug` · `info` · `warn` · `error` |
| `--log-dir <dir>` | `<output>/_logs` | โฟลเดอร์เก็บไฟล์ log |
| `--sharp-concurrency <n\|auto>` | `1` เมื่อ workers>1 | จำกัดเธรดภายในของ libvips (ขั้นสูง — ดู RESEARCH.md) |
| `--quiet` | ปิด | ซ่อน progress bar, แสดงเฉพาะ error |
| `-V, --version` | — | ดูเวอร์ชัน |

## กติกาที่ควรรู้

- **ปลายทาง default คือโฟลเดอร์ข้างเคียง** `<input>-resized` ไม่ใช่ใน input — ทำให้รันซ้ำได้ปลอดภัย ไม่มีวันประมวลผลผลลัพธ์ของตัวเอง
- **รูปที่เล็กกว่า limit จะยังถูกแปลงเป็น JPG** (ขนาดไม่ขยาย) — เพื่อให้ทั้งชุดเป็น JPG ล้วนตามโจทย์
- **EXIF orientation ถูกแปลงเป็นพิกเซลจริง** ทุกรูปจึงหมุนถูกทิศทางในทุกโปรแกรม
- **ไฟล์เสียไม่ทำให้ทั้งชุดล้ม** — บันทึก error ต่อไฟล์ใน log แล้วทำไฟล์อื่นต่อ (exit code = 2)
- **ชื่อไฟล์ผลลัพธ์**: ใช้ชื่อเดิมเปลี่ยนนามสกุลเป็น `.jpg` ถ้าชนกับไฟล์เดิมที่มีอยู่แล้วและไม่ได้ใส่ `--overwrite` จะถือว่า skipped
- **GIF/SVG** ใช้เฟรม/หน้าแรกเท่านั้น
- **รองรับ input**: jpg, jpeg, jpe, jfif, png, webp, tif, tiff, gif, svg, avif, heic, heif
- **exit code**: `0` สำเร็จทั้งหมด, `2` มีไฟล์ error บางไฟล์, `1` ระบบล้ม (เช่น พาธผิด)

## เช็กลิสต์ก่อนย่อรูปชุดใหญ่

1. มีพื้นที่ดิสก์เหลือพอสำหรับโฟลเดอร์ผลลัพธ์ (รูป JPG 3800px เฉลี่ย ~2–6 MB/รูป)
2. ลอง `--dry-run` กับโฟลเดอร์จริงดูจำนวนไฟล์/ขนาดรวมจาก log ก่อน
3. ย่อชุดทดลองเล็ก ๆ (50–100 รูป) ส่องคุณภาพก่อนตัดสินใจ `-q`
4. รันชุดจริงตอนเครื่องว่าง (งานนี้กิน CPU เต็มที่โดยดีไซน์)
5. เสร็จแล้วเปิดไฟล์ `summary.json` ดูสรุป + เช็ก `errors` ว่าเป็น 0
