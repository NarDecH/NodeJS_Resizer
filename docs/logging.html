ระบบไฟล์ log

ทุกการรันสร้าง log ครบชุด — ทั้งแบบมนุษย์อ่านและแบบเครื่องวิเคราะห์ เพื่อดีบักและปรับแต่งได้ลงลึกทุกไฟล์

ไฟล์ที่ได้ต่อ 1 รัน (อยู่ใน <output>/_logs/)

ไฟล์ผู้อ่านเนื้อหา
run-YYYYMMDD-HHMMSS.logคนหัวรัน (เวอร์ชัน/เครื่อง/ค่า config) + ผลต่อไฟล์ละเอียด + top-5 + สรุป
run-….jsonlเครื่องJSON Lines — 1 event ต่อบรรทัด เอาเข้า Excel/Python/jq ได้ทันที
run-….summary.jsonคน+เครื่องสรุปตัวเลขทั้งรัน: นับไฟล์, throughput, ขนาด, slowest, saving สูงสุด
latest.log / latest.jsonlคนสำเนาของรันล่าสุดเสมอ — ไม่ต้องไล่ชื่อไฟล์

ทุกบรรทัดมี: เวลาที่ผ่านมา (t+), สถานะ, พาธ input/output, มิติก่อน→หลัง (คิด EXIF rotation แล้ว), ฟอร์แมตต้นทาง, ขนาดก่อน→หลัง, ระยะเวลา (ms) และหมายเหตุ

ชนิด event ในไฟล์ .jsonl

eventความหมายฟิลด์สำคัญ
run_startเริ่มรัน + config ทั้งหมดversion, input, output, maxSize, quality, workers, recursive, overwrite, dryRun, cpus
file_convertedแปลงสำเร็จinput, output, widthIn/heightIn, widthOut/heightOut, formatIn, bytesIn, bytesOut, durationMs, note
file_skippedข้าม (มีผลลัพธ์แล้ว = resume)input, output, bytesOut, note
file_errorไฟล์เสีย/อ่านไม่ได้input, note (ข้อความ error เต็ม)
sharp_warninglibvips เตือน (ไฟล์เสียเล็กน้อยแต่อ่านได้)input, message
scan_excluded_output_dirตัดโฟลเดอร์ output ออกจากการสแกนdir
scan_doneสแกนจบfiles, entriesSeen
run_endสรุปท้ายรันตัวเลข summary ทั้งหมด

ระดับ log (--log-level): debug < info < warn < error — default info

สูตรวิเคราะห์ที่ใช้บ่อย

# ไฟล์ไหน error บ้าง
grep file_error <output>/_logs/latest.jsonl

# 10 ไฟล์ที่ใช้เวลานานสุด (jq)
jq -c 'select(.event=="file_converted") | {input, ms:.durationMs}' \
  <output>/_logs/latest.jsonl | sort -t: -k2 -rn | head

# สถิติขนาดไฟล์ผลลัพธ์ (Python)
python -c "import json,statistics as s;rows=[json.loads(l) for l in open(r'logs/latest.jsonl',encoding='utf8')];kb=[r['bytesOut']/1024 for r in rows if r.get('event')=='file_converted'];print(len(kb),round(min(kb)),round(s.median(kb)),round(max(kb)))"
ปรัชญาของระบบ log เขียนครั้งเดียวตอน flush — งานหลักไม่เสีย I/O กับ log (ผลลัพธ์รูปยังปลอดภัยเพราะเขียน atomic ต่อรูป) · สองรูปแบบคู่กันเสมอ — .log ตอบ "เกิดอะไรขึ้น" ให้คน, .jsonl ตอบ "ตัวเลขไหน" ให้เครื่อง · config ฝังทุกรัน — เทียบข้ามรันเพื่อ tuning ได้ทันที · summary.json แยกไฟล์ — เปิดดูเร็วไม่ต้อง parse log ยาว
