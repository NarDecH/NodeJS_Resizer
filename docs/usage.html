วิธีใช้งาน

เลือกได้ทั้งดับเบิลคลิกแบบถาม-ตอบ หรือสั่งผ่าน command line แบบเต็มรูปแบบ — ทุกโหมดเขียน log ละเอียดให้เหมือนกัน

3 วิธีเริ่มใช้งาน

1

โปรแกรมสำเร็จรูป (ง่ายสุด, Windows)

โหลด …win-x64-portable.zip จาก หน้าดาวน์โหลด → แตก zip → ดับเบิลคลิก resize.bat → ลากโฟลเดอร์รูปใส่หน้าต่าง → Enter มี Node runtime + ไลบรารีครบในตัว ใช้จาก USB ก็ได้

2

ผ่าน Node.js / npm

git clone → npm install → npm start เข้าโหมดถาม-ตอบเหมือนดับเบิลคลิก เหมาะกับ macOS / Linux / Windows ที่มี Node อยู่แล้ว

3

สั่งงานเต็มรูปแบบ

node src/cli.js -i "D:\Photos" -o "D:\Photos-resized" -s 3800 -q 82 — ควบคุมทุกพารามิเตอร์ ใส่สคริปต์/Task Scheduler ได้

ตัวอย่างคำสั่งที่ใช้บ่อย

# ทั้งโฟลเดอร์ ยาวสุด 3800px (ค่าเริ่มต้น) ผลลัพธ์อยู่โฟลเดอร์ข้าง ๆ
node src/cli.js -i "D:\Photos"

# คุณภาพสูงขึ้น + ไฟล์เล็กลงแบบ mozjpeg (ช้าลง 2-3 เท่า)
node src/cli.js -i "D:\Photos" -q 92 --mozjpeg

# ทำภาพสำหรับเว็บ 1920px เฉพาะโฟลเดอร์เดียว
node src/cli.js -i "D:\Gallery" -s 1920 --no-recursive

# ทดลองดูก่อนโดยไม่เขียนไฟล์
node src/cli.js -i "D:\Photos" --dry-run

# รันต่อจากที่ค้าง (ข้ามไฟล์ที่เสร็จแล้วอัตโนมัติ)
node src/cli.js -i "D:\Photos"

# เก็บ EXIF/GPS ไว้ (งานถ่ายภาพที่ต้องการข้อมูลกล้อง)
node src/cli.js -i "D:\Wedding" --keep-metadata

ตารางตัวเลือกทั้งหมด

ตัวเลือกค่าเริ่มต้นความหมาย
-i, --input <dir>ถามตอนรันโฟลเดอร์ต้นทาง (หรือไฟล์เดียว) — ลากวางใส่หน้าต่างได้เลย
-o, --output <dir><input>-resizedโฟลเดอร์ปลายทาง; เก็บโครงสร้างโฟลเดอร์ย่อยเดิม
-s, --max-size <px>3800ความยาวด้านที่ยาวที่สุดที่ยอมให้มี (16–30000)
-q, --quality <n>82คุณภาพ JPEG 1–100
-w, --workers <n>autoจำนวนรูปที่ประมวลผลพร้อมกัน (auto = จำนวนคอร์ CPU)
--no-recursiverecursiveไม่ลงไปในโฟลเดอร์ย่อย
--overwriteปิดแปลงซ้ำทุกไฟล์ (default ข้ามไฟล์ที่มีผลลัพธ์แล้ว = resume)
--keep-metadataปิดเก็บ EXIF/GPS (default ตัดทิ้ง แต่คง ICC colour profile เสมอ)
--mozjpegปิดใช้ mozjpeg — เล็กลง ~30% แต่ช้าลง 2–3 เท่า
--dry-runปิดวางแผน + log อย่างเดียว ไม่เขียนรูป
--log-level <lvl>infodebug · info · warn · error
--log-dir <dir><output>/_logsโฟลเดอร์เก็บไฟล์ log
--sharp-concurrency <n|auto>1 เมื่อ workers>1จำกัดเธรดภายใน libvips (ขั้นสูง — ดู RESEARCH)
--quietปิดซ่อน progress bar แสดงเฉพาะ error
กติกาที่ควรรู้ ปลายทาง default คือโฟลเดอร์ข้างเคียง <input>-resized ไม่ใช่ใน input — รันซ้ำได้ปลอดภัยเสมอ · รูปที่เล็กกว่า limit จะถูกแปลงเป็น JPG เช่นกัน (ไม่ขยายขนาด) เพื่อให้ทั้งชุดเป็น JPG ล้วน · ไฟล์เสียไม่ทำทั้งชุดล้ม (exit code 2 แล้วดู log) · GIF/SVG ใช้เฟรม/หน้าแรก

เช็กลิสต์ก่อนย่อรูปชุดใหญ่

1

เผื่อพื้นที่ดิสก์

รูป JPG 3800px เฉลี่ย ~2–6 MB/รูป ตรวจว่าดิสก์ปลายทางเหลือพอ

2

dry-run ก่อน

--dry-run แล้วเปิด summary.json ดูจำนวนไฟล์และขนาดรวม

3

ทดลองชุดเล็ก

ย่อ 50–100 รูป ส่องคุณภาพจริงก่อนตัดสินใจค่า -q

4

รันจริง + ตรวจ log

เสร็จแล้วเช็ก errors ใน summary และค้น file_error ใน latest.jsonl
